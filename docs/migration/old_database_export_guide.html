旧系统数据库与附件导出说明

本文档配合 ALIYUN_WORKBENCH_OLD_DATABASE_EXPORT_CLEAN.txt 使用。 目标是在旧系统服务器上导出一个尽量完整的迁移包，供新系统导入脚本恢复数据库、 附件和必要运行上下文。

核心结论： 如果你能 root 登录旧系统服务器，即使不记得数据库密码，也通常可以导出。 因为数据库连接串保存在旧系统部署目录的 .env.production 中， 默认路径是 /opt/wailearning-old-system/current/.env.production。

整体迁移思路

  1. 旧系统停止或暂停写入，避免导出过程中又产生新作业、附件、通知或成绩。
  2. 在旧系统服务器执行干净版 Workbench 导出操作流。
  3. 导出脚本读取旧系统环境文件，使用 pg_dump -Fc 生成 PostgreSQL 自定义格式备份。
  4. 导出脚本收集上传附件目录，并保存运行配置、服务配置、nginx 配置和 git commit 快照。
  5. 把生成的 /root/wailearning-migration/<label>.tar.gz 复制到新系统服务器。
  6. 新系统执行导入脚本：先备份新库，再 pg_restore 旧库，解压附件，最后运行新系统 bootstrap 做兼容性修复。
  7. 在新系统上用管理员、老师、学生、家长入口做 smoke test，再决定是否切换域名或开放访问。

导出操作流

推荐直接复制仓库文件 docs/migration/ALIYUN_WORKBENCH_OLD_DATABASE_EXPORT_CLEAN.txt 到阿里云 Workbench 执行。该文件刻意避免长路径出现在执行命令行里，防止复制粘贴时真实换行 把路径切成两段。

默认只需要检查这几个变量：

变量默认值说明
ENV_FILE /opt/wailearning-old-system/current/.env.production 旧系统环境文件。里面应包含 DATABASE_URL，所以不需要你记住数据库密码。
RELEASE_DIR /opt/wailearning-old-system/current 旧系统代码目录。用于记录 git commit，也用于推断可能的上传目录。
MIGRATION_OUTPUT_DIR /root/wailearning-migration 迁移包输出目录。root 登录时默认可写。
MIGRATION_LABEL old-to-new-时间戳 输出文件名的一部分。通常不用改。

导出包包含什么

文件用途
old-system.dump 旧系统 PostgreSQL 数据库备份，使用 pg_dump -Fc 生成，供新系统 pg_restore。
old-uploads.tar.gz 旧系统上传附件归档。脚本会尽量收集 UPLOADS_DIR、 release 下的 uploads、应用根目录和 shared uploads。
old-env.production 旧系统环境文件快照。里面可能包含敏感信息，不要公开发给无关人员。
old-systemd.service 旧后端 systemd 配置快照，帮助排查服务名、端口、工作目录。
old-nginx.conf 旧 nginx 配置快照，帮助确认路由、域名和静态文件入口。
old-git-commit.txt 旧系统代码 commit，用于确认迁移来源版本。
upload-roots-included.txt 实际被收集到的上传目录列表。导入后如果附件缺失，先看这个文件。
attachment-references.tsv 数据库内作业、提交、资料、通知引用到的附件 URL 清单，用于和实际文件归档比对。
manifest.txt 导出时间、路径、主要文件名等总清单。

为什么不只导出数据库

旧系统不是所有资料都在数据库里。数据库里通常只保存附件 URL、附件名称、作业/资料正文、成绩、 用户、班级、课程等结构化数据；用户上传的真实文件在服务器文件系统的 uploads 目录下。 如果只拿 pg_dump，新系统里会看到附件记录，但点击下载可能 404。

常见失败与排查信息

现象优先检查
提示找不到 ENV_FILE 旧系统不是默认部署路径。用下面命令找真实路径，再改操作流顶部变量。 find /opt /root -name .env.production 2>/dev/null
提示环境文件缺少 DATABASE_URL 说明旧系统不是按当前部署脚本生成，或环境变量在 systemd 里。 查看 systemctl cat wailearning-old-system.service。
pg_dump 不存在 旧服务器缺少 PostgreSQL client。Ubuntu 可安装 postgresql-client。 脚本不会猜测数据库密码，仍从 env 读。
导出成功但附件缺失 查看包内 upload-roots-included.txt 和 attachment-references.tsv。如果旧系统曾自定义上传目录， 把该目录设为 UPLOADS_DIR 后重跑。
导入新系统后页面空白或登录后无数据 先确认新系统导入脚本是否完成 bootstrap；再查新系统后端日志和数据库计数。不要只看 nginx 首页。
Workbench 粘贴后命令被截断 使用干净版 txt。该版本没有长 raw URL 执行行，也没有手写 heredoc 输入段。

导入新系统的对接要点

  • 新系统应先完成基础部署，确认 /api/health 正常。
  • 导入前要把迁移包复制到新系统服务器，例如 /root/old-to-new-xxxx.tar.gz。
  • 新系统导入脚本会先备份新库，再恢复旧库，再解压附件。
  • 导入后新系统 bootstrap 会补新系统缺少的表、字段、默认配置和兼容数据。
  • 如果新系统部署时 INIT_DEFAULT_DATA=true，导入后的 bootstrap 可能同时保留旧系统迁移数据并补充新系统演示数据。
  • 导入后先用管理员检查学生、课程、作业、资料，再用老师、学生、家长分别登录验证权限和可见数据。
  • 域名切换前保留旧系统服务器和迁移包，不要立即销毁旧库。
给 LLM 排错时建议一起提供： Workbench 执行的完整代码流、终端报错最后 200 行、迁移包内 manifest.txt、 upload-roots-included.txt、attachment-references.tsv， 以及旧系统和新系统的 .env.production 中脱敏后的数据库类型、端口、路径字段。 不要直接公开真实数据库密码、API key、SECRET_KEY。

成功后你应该看到什么

脚本完成时会输出类似：

迁移包导出完成：/root/wailearning-migration/old-to-new-20260521120000.tar.gz
请把该文件复制到新系统服务器，例如：
scp /root/wailearning-migration/old-to-new-20260521120000.tar.gz \
  root@<NEW_ECS_IP>:/root/

如果你只是要先备份，不立刻迁移，也可以把这个 tar.gz 下载到本地保存。
