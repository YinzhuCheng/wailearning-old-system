完整主流程

重要： “导出完成”不代表文件已经自动到了 Windows。 在这套工具包里，下载到 Windows 和 Windows 本地 SHA256 校验，是正式主流程的一部分，不是附加建议。

按偏好选哪个代码流

偏好 先开哪个文件 原因
最稳、最少出意外 01_WORKBENCH_DIRECT_PASTE.txt 脚本内嵌，不依赖 GitHub raw；最适合第一次给执行者。
后续要反复拿最新版脚本 02_WORKBENCH_DOWNLOAD_SCRIPT.txt 从 GitHub 拉最新版脚本，适合后续维护和重复执行。
先看图示再做 20_WORKBENCH_DOWNLOAD_TO_WINDOWS_VISUAL_GUIDE.html 专门解释 Workbench 里如何把包带回 Windows。

出错时给 LLM 哪些文档和代码

  • 入口页：00_START_HERE_EXPORTER.html
  • 你实际执行的代码流：01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt
  • 主脚本：03_standalone_old_export.sh
  • 旧服务器校验脚本：04_verify_export_bundle.sh
  • 如果问题出在 Windows 下载后：05_windows_verify_bundle.ps1
  • 复杂版排障说明：90_DEEP_TROUBLESHOOTING_FOR_LLM.html
  • Workbench 最近 200 行输出
  • 若包已生成：包内 manifest.txt、db-table-counts.tsv、upload-roots-included.txt
最小原则： 不要只给 LLM 一句 “导出失败了” 或只给最后一行报错。 至少把“你选的代码流 + 主脚本 + 最近 200 行终端输出”一起给出去。
