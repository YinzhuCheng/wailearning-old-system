旧系统导出工具包入口

这里是整个 standalone-old-export-kit 的总入口。 这个页面只做目录和入口，不承担复杂排版。 你可以把它当成一份可点击的“增强版 markdown”。

先怎么选

最稳妥的导出者路线 先打开 exporter-pack/00_START_HERE_EXPORTER.html， 然后直接用 01_WORKBENCH_DIRECT_PASTE.txt。
重复导出 / 拉最新版脚本 先打开 exporter-pack/00_START_HERE_EXPORTER.html， 然后用 02_WORKBENCH_DOWNLOAD_SCRIPT.txt。
协调人 / 排障者 / LLM 协调人先看 10_COORDINATOR_NOTES.html； 出问题时看 90_DEEP_TROUBLESHOOTING_FOR_LLM.html。

主流程

  1. 先打开 导出者入口页。
  2. 在旧服务器的 Workbench 里执行导出代码流。
  3. 在旧服务器上运行 04_verify_export_bundle.sh 做包校验。
  4. 把 .tar.gz 和 .sha256 下载到 Windows。
  5. 在 Windows 上运行 05_windows_verify_bundle.ps1 做 SHA256 校验。
  6. 若任何一步失败，把代码流、脚本和终端输出一起给 LLM。
重要： “导出完成”只表示文件在旧服务器上生成了，不代表已经自动到了 Windows。 下载到 Windows 和 Windows 本地 SHA256 校验，是正式主流程的一部分。

按偏好选哪个文件

最稳、最少出意外 01_WORKBENCH_DIRECT_PASTE.txt。 整段复制进 Workbench，不依赖 GitHub raw。
后续反复执行 02_WORKBENCH_DOWNLOAD_SCRIPT.txt。 先下载脚本再执行，适合后续维护。
先看下载图示 20_WORKBENCH_DOWNLOAD_TO_WINDOWS_VISUAL_GUIDE.html。 专门讲怎么把包从 Workbench 带回 Windows。

出错时给 LLM 哪些材料

  • 00_START_HERE_EXPORTER.html
  • 01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt
  • 03_standalone_old_export.sh
  • 04_verify_export_bundle.sh
  • 05_windows_verify_bundle.ps1
  • 90_DEEP_TROUBLESHOOTING_FOR_LLM.html
  • Workbench 最近 200 行输出
  • 若包已生成：manifest.txt、db-table-counts.tsv、upload-roots-included.txt
最小原则：不要只给一句报错。至少把“实际用了哪个代码流 + 主脚本 + 终端输出”一起给出去。
