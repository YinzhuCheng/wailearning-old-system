Workbench 下载到 Windows 说明

这页只讲一件事：旧服务器已经生成迁移包后，怎么把它稳妥地下载到 Windows。 这里不再画复杂流程图，只保留最稳的步骤。

先说清楚：
  • 代码流只负责在旧服务器上生成迁移包；它不会自动把文件写到你的 Windows 电脑。
  • 02_WORKBENCH_DOWNLOAD_SCRIPT.txt 里的“下载脚本”，指的是旧服务器从 GitHub 下载导出脚本，不是自动下载迁移包到 Windows。
  • 从旧服务器到 Windows 这一步，需要用 Workbench 文件管理器手工下载，或在 Windows 上另行使用 scp/sftp/rsync、OSS 等方式取回文件。
先确认旧服务器上已经有迁移包： 
/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz
/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz.sha256
这里的 .tar.gz 是必须下载的迁移包；.sha256 是可选哈希校验文件。/root/wailearning-migration 是默认导出目录。若脚本输出了不同路径，或你改过 OUT_DIR，以后都以脚本最后打印出来的实际路径为准。
如果你忘了文件名：回到 Workbench 终端运行下面命令，找时间最新的 .tar.gz： 
ls -lh /root/wailearning-migration/old-to-new-*.tar.gz
看到的完整路径就是文件管理器里要找的路径。

阿里云官方依据

  • 官方文档： 通过Workbench上传下载或管理ECS上的文件。 这页说明 Workbench 可以在浏览器里管理 ECS 文件，文件管理功能只支持通过 Workbench 终端连接登录；如果用会话管理（SSM）连接，因为没有文件传输通道，所以不能用这个下载入口。
  • 备选方案文档： 通过sftp/scp/rsync向Linux实例传输文件。 如果 Workbench 下载失败、文件太大或需要断点续传，可以从 Windows 本机侧改用 scp、sftp 或 rsync 拉取文件。

最稳的下载方式

  1. 在 Workbench 里确认自己用的是终端连接，不是会话管理连接（会话管理通常没有文件管理/下载入口）。
  2. 如果是 Workbench 2.0，在左侧菜单栏找到文件管理图标并点击，即可看到文件树。
  3. 如果是 Workbench 1.0，在顶部菜单栏选择“文件” -> “打开新文件树”。如果你看不到顶部菜单，可在终端区域右键尝试显示菜单栏。
  4. 在文件树里找到导出目录，通常是 /root/wailearning-migration。
  5. 在文件树里右键点击想下载的 .tar.gz 文件，即可看到“下载”按钮或“下载文件”菜单项。
  6. 可选：如果你想做哈希校验，再用同样方式下载同名 .sha256 文件。
  7. 把下载到的文件放到 Windows 的一个短路径目录里，例如 C:\Users\you\Downloads\wailearning\。这里的 you 只是示例，换成你当前 Windows 用户名或你实际保存的位置。
  8. 可选：按下面“Windows 本地校验怎么运行”执行 05_windows_verify_bundle.ps1。
最容易踩的坑：
  • 不要把 Windows 本地校验或哈希校验当成主流程卡点。主流程必须完成的是把 .tar.gz 下载到 Windows；如果你想加强确认，再跑本地校验或下载同名 .sha256 做哈希比对。
  • 不要在 Workbench 里粘贴很长的本地路径，路径太长时容易自动换行。
  • 如果看不到文件下载入口，先检查连接方式（终端连接 vs 会话管理），不要先怀疑脚本。
  • 如果迁移包很大，Workbench 文件下载可能会受限或很慢。优先按“能下载就用 Workbench”，否则看下面“下载失败怎么办”。

下载失败怎么办

  • 没有文件管理入口：通常是用了会话管理连接，或菜单栏被隐藏。优先改用 Workbench 的“终端连接”重连；其次在终端区域右键切换“显示/隐藏菜单栏”。
  • 文件太大/下载很慢：改用 scp/sftp/rsync 从 Windows 本机拉取，或上传到对象存储（OSS）再下载。更详细的兜底方案见 90_DEEP_TROUBLESHOOTING_FOR_LLM.html。
  • 权限不足：请确认是 root 用户，至少能读取导出目录。

可选：Windows 本地校验怎么运行

  1. 在 Windows 上打开 PowerShell。
  2. 切到这个工具包的 exporter-pack 目录，也就是 05_windows_verify_bundle.ps1 所在目录。
  3. 把下面命令里的迁移包路径，改成你刚下载到 Windows 的真实 .tar.gz 路径。
推荐写法：先进入脚本目录，再运行脚本。 
powershell -ExecutionPolicy Bypass -File .\05_windows_verify_bundle.ps1 `
  -BundlePath C:\Users\you\Downloads\wailearning\old-to-new-20260521120000.tar.gz
这条命令里的 .\05_windows_verify_bundle.ps1 表示“当前目录下的脚本”。如果你没有先切到 exporter-pack，就要把 -File 后面改成脚本的完整路径。
完整路径写法：不切目录也能运行。 
powershell -ExecutionPolicy Bypass -File C:\path\to\exporter-pack\05_windows_verify_bundle.ps1 `
  -BundlePath C:\Users\you\Downloads\wailearning\old-to-new-20260521120000.tar.gz
把 C:\path\to\exporter-pack\05_windows_verify_bundle.ps1 换成你这份工具包里脚本的真实位置。

可选：哈希校验

如果你同时下载了同名 .sha256 文件，可以把它传给 05_windows_verify_bundle.ps1 做 SHA256 比对。 这一步能更明确地判断下载过程中有没有损坏；如果你嫌麻烦，也可以先跳过，出错时重新导出或重新下载。 

powershell -ExecutionPolicy Bypass -File .\05_windows_verify_bundle.ps1 `
  -BundlePath C:\Users\you\Downloads\wailearning\old-to-new-20260521120000.tar.gz `
  -Sha256File C:\Users\you\Downloads\wailearning\old-to-new-20260521120000.tar.gz.sha256
如果你选择本地校验：看到“校验通过”表示这个检查通过。脚本会检查迁移包是否存在、文件大小是否为 0，并在 Windows 自带 tar.exe 可用时尝试读取压缩包目录；如果传了 -Sha256File，还会额外比对 SHA256。
