Workbench 下载到 Windows 图示说明

这个页面只讲一件事：旧服务器里已经有迁移包后，怎么把它稳妥地下载到 Windows， 并避免把“下载失败 / 文件损坏 / 连接方式不对”误判成脚本问题。

先确认你已经有这两个文件

/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz
/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz.sha256

如果你还没有这两个文件，请先回到 00_START_HERE_EXPORTER.html，完成导出和旧服务器校验。

示意图

1

确认连接方式正确

如果你在 Workbench 里看不到文件树、文件管理按钮、或下载入口， 先不要怀疑脚本。先判断自己是不是用了 会话管理连接。

阿里云官方文档当前明确说明：会话管理连接不支持文件管理。 需要改成 终端连接。

2

进入导出目录

在旧服务器终端里记下导出目录，通常是： 

/root/wailearning-migration

目录里至少应该看到一个 .tar.gz 和一个同名 .sha256。

3

下载两个文件

只下载这两个即可：

  • old-to-new-....tar.gz
  • old-to-new-....tar.gz.sha256

不要只下载前者。否则 Windows 端无法判断下载过程是否损坏。

4

PowerShell 校验

powershell -ExecutionPolicy Bypass -File .\05_windows_verify_bundle.ps1 `
  -BundlePath C:\Users\you\Downloads\old-to-new-20260521120000.tar.gz `
  -Sha256File C:\Users\you\Downloads\old-to-new-20260521120000.tar.gz.sha256

看到“校验通过”再继续交给迁移接手者。

最常见误区： 导出者看到 Workbench 里打印了“导出完成”，就以为文件已经到了本地 Windows。 这不对。导出完成只代表文件已经在旧服务器生成，下载动作还没有发生。

下载失败时怎么分辨问题在哪

现象 更可能的原因 先做什么
看不到文件树或下载按钮 连接方式不对，常见是会话管理连接 改用终端连接
文件能下载，但特别慢 Workbench 高峰期传输慢 等待，或改用 scp / sftp / OSS 中转
Windows 上校验 SHA256 不匹配 下载过程损坏 / 截断 / 混淆了文件版本 重新下载 .tar.gz 和 .sha256
找不到 .sha256 导出脚本运行的是旧版或服务器工具降级 先回看导出终端输出，必要时重新跑最新版流程
官方依据： 我核对过阿里云官方文档。当前文档明确支持 Linux 实例在 Workbench 中下载文件到本地， 同时也明确写了会话管理连接不支持文件管理，高峰期上传下载速度可能下降。
