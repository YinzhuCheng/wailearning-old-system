协调人说明

这个页面是给“你”这种协调人看的，不是给最终执行导出的同事看的。 目的是帮你把文件一次性交付到位，避免来回补充。

最简单的发法： 直接把整个 exporter-pack 文件夹发给导出执行者，并告诉他 “先打开 00_START_HERE_EXPORTER.html，按顺序做”。

这个文件夹里哪些文件是给谁看的

文件 主要读者 用途
00_START_HERE_EXPORTER.html 导出执行者 极简入口与顺序说明。
01_WORKBENCH_DIRECT_PASTE.txt 导出执行者 首选执行版，整段复制进 Workbench。
02_WORKBENCH_DOWNLOAD_SCRIPT.txt 导出执行者 备选执行版，从 GitHub 拉脚本。
04_verify_export_bundle.sh 导出执行者 旧服务器导出完成后的自检。
05_windows_verify_bundle.ps1 导出执行者或接收包的人 Windows 本地核对下载包没坏。
06_post_import_verify.sh 迁移接手者 新系统导入后的数据与附件对账。
90_DEEP_TROUBLESHOOTING_FOR_LLM.html 排障者 / LLM 复杂版说明、踩坑分析、兼容性与提问模板。
不要只发代码流 txt。 如果你只把 01_WORKBENCH_DIRECT_PASTE.txt 发给执行者， 很容易出现“导出成功了，但不知道怎么下到 Windows”这种断层。 现在要么发整个文件夹，要么至少一起发： 00_START_HERE_EXPORTER.html、 01_WORKBENCH_DIRECT_PASTE.txt、 04_verify_export_bundle.sh、 05_windows_verify_bundle.ps1。

建议你的转述话术

你可以直接把下面这段话发给执行者：

“请打开文件夹里的 00_START_HERE_EXPORTER.html。 优先执行 01_WORKBENCH_DIRECT_PASTE.txt。 导出完成后不要退出，继续按页面说明在旧服务器执行校验、下载到 Windows、 然后在 Windows 上执行 05_windows_verify_bundle.ps1。 如果任何一步失败，把 90_DEEP_TROUBLESHOOTING_FOR_LLM.html 和终端输出一起发回来。”
