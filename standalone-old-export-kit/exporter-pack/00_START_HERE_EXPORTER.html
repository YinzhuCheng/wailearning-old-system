旧系统导出者入口包

这是一份给旧系统维护者的纯入口包。你只要打开这个文件夹，先看 00_START_HERE_EXPORTER.html，然后按里面的主流程做即可。

先用哪个版本：
  1. 01_WORKBENCH_DIRECT_PASTE.txt（首选，整段复制到 Workbench；不依赖 GitHub raw）。
  2. 02_WORKBENCH_DOWNLOAD_SCRIPT.txt（备选，先下载脚本再执行）。

主流程

  1. 在旧服务器 Workbench 里执行导出代码流。
  2. 导出后先运行 04_verify_export_bundle.sh 做旧服务器校验。
  3. 把 .tar.gz 下载到 Windows；.sha256 只是可选哈希校验文件。
  4. 把下载到 Windows 的 .tar.gz 交给迁移接手者。
  5. 可选：按 20_WORKBENCH_DOWNLOAD_TO_WINDOWS_VISUAL_GUIDE.html 里的命令运行 05_windows_verify_bundle.ps1 做 Windows 本地校验。

导出后文件在哪里

默认导出目录：/root/wailearning-migration
迁移包文件名：old-to-new-YYYYMMDDHHMMSS.tar.gz
可选哈希文件：old-to-new-YYYYMMDDHHMMSS.tar.gz.sha256

脚本结束时会在 Workbench 终端里打印实际路径，例如 /root/wailearning-migration/old-to-new-20260521120000.tar.gz。 后续旧服务器校验、Workbench 文件管理器下载、Windows 本地可选校验，都以终端最后打印的实际路径和文件名为准。

如果你没看清脚本最后输出，可以在 Workbench 终端里运行下面这条命令找最新迁移包： 

ls -lh /root/wailearning-migration/old-to-new-*.tar.gz

旧服务器校验怎么做

导出脚本结束后，Workbench 终端会打印一条可以直接复制的校验命令，通常长这样： 

bash /tmp/verify_export_bundle.sh /root/wailearning-migration/old-to-new-20260521120000.tar.gz

你不需要自己猜脚本放在哪里。优先复制终端最后给出的 bash ... old-to-new-....tar.gz 命令； 如果命令里的时间戳不同，用你终端实际看到的那一条。

关键提醒：“导出完成”只表示旧服务器生成包，不表示文件已经到 Windows。 “下载到 Windows”是主流程的一部分；Windows 本地校验是可选推荐检查。 默认按 Workbench 文件管理器下载即可：在左侧菜单栏找到文件管理图标并点击，即可看到文件树； 在文件树里右键点击想下载的 .tar.gz 文件，即可看到“下载”按钮或“下载文件”菜单项。 scp/sftp/rsync、OSS 只是 Workbench 下载失败或大文件很慢时的备选方案。

下载到 Windows 的说明

如果你想要更聚焦的下载说明，打开 20_WORKBENCH_DOWNLOAD_TO_WINDOWS_VISUAL_GUIDE.html。

出错时给 LLM 什么

  • 你实际用了哪份代码流：01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt。
  • 主脚本：03_standalone_old_export.sh。
  • 旧服务器校验脚本：04_verify_export_bundle.sh。
  • Workbench 最近 200 行输出。
  • 如果已经生成包，再带上 manifest.txt、db-table-counts.tsv、upload-roots-included.txt。
  • 复杂排障页：90_DEEP_TROUBLESHOOTING_FOR_LLM.html。
最小建议：不要只发一句“报错了”。至少把“用了哪个代码流 + 哪个脚本 + 终端输出”一起给出去。
