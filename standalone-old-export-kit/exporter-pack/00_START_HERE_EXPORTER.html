旧系统导出者入口包

这个文件夹是专门给旧系统导出执行者的。 如果你只想顺利完成工作，不想研究细节，就按这个页面的顺序往下走。 这个页面只保留最少信息，复杂排障说明放在下级文档。

你现在应该先用哪个版本

首选，最稳妥 用 01_WORKBENCH_DIRECT_PASTE.txt。 这是整段直接粘贴到 Workbench 的版本，不依赖 GitHub raw。
备选，适合以后反复执行 用 02_WORKBENCH_DOWNLOAD_SCRIPT.txt。 这是先下载脚本再执行的版本，适合后续复用最新版脚本。

最短工作流程

  1. 先在旧服务器的 Workbench 里执行导出代码流。
  2. 导出完成后，不要离开旧服务器，先运行 04_verify_export_bundle.sh 做包校验。
  3. 把 .tar.gz 和同名 .sha256 下载到 Windows。
  4. 在 Windows 上运行 05_windows_verify_bundle.ps1 做 SHA256 校验。
  5. 校验通过后，再把包交给迁移接手者。
关键提醒： “导出完成”只代表文件已经在旧服务器生成，不代表已经自动到了 Windows。 下载到 Windows 和 Windows 本地校验，是正式步骤，不要跳过。

如果你需要图示版说明

打开 20_WORKBENCH_DOWNLOAD_TO_WINDOWS_VISUAL_GUIDE.html。 它专门讲如何从 Workbench 把迁移包带回 Windows。

如果出错，给 LLM 哪些东西

  • 你实际执行的代码流：01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt
  • 主脚本：03_standalone_old_export.sh
  • 旧服务器校验脚本：04_verify_export_bundle.sh
  • Workbench 最近 200 行输出
  • 如果包已生成：manifest.txt、db-table-counts.tsv、upload-roots-included.txt
  • 复杂版排障说明：90_DEEP_TROUBLESHOOTING_FOR_LLM.html
最小原则：不要只给一句报错。至少把“实际用了哪个代码流 + 主脚本 + 终端输出”一起给出去。
