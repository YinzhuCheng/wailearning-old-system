复杂版排障说明

这页不是给普通执行者看的，而是给排障者、接手迁移的人、以及 LLM 看的问题包。 目标是把“哪里坏了、该看什么、该怎么问”一次写清楚。

给 LLM 的最小文件集：
  • 01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt
  • Workbench 最近 200 行输出
  • 03_standalone_old_export.sh
  • 04_verify_export_bundle.sh 的输出
  • 若包已生成，再加上 manifest.txt、db-table-counts.tsv、upload-roots-included.txt、attachment-files-missing.tsv
  • 若已导入，再加 06_post_import_verify.sh 的输出

先判断故障层

  • 问题是在导出阶段、下载到 Windows 阶段，还是导入后验证阶段？
  • Workbench 当前是终端连接还是会话管理连接？
  • 失败的是数据库导出、附件收集、下载、还是新库对账？
  • 是否只是权限问题，例如不是 root，或者无权读取目标文件？
我刻意避免的坑：
  • 长命令被 Workbench 自动折行，结果命令被截成两段。
  • 只看到“导出完成”，却误以为文件已经到 Windows。
  • 下载后没有在 Windows 本地跑校验，误以为“文件下载完成”就等于“包可用”。
  • 用会话管理连接去找文件管理功能，结果根本没有下载入口。
  • 只看数据库里的附件 URL，不看落盘文件是否真的存在。
  • 忽略 attachment-files-missing.tsv，误以为所有外部附件都已经打进包里。

兼容性判断要点

这里的“兼容”不只是脚本语法，也包括 Workbench 版本、登录方式、包管理器、旧系统路径差异， 以及服务器是否自带 sha256sum、psql、pg_dump。

  • Workbench 1.0 / 2.0：界面可能不同，但文件下载思路相同。
  • 终端连接 / 会话管理连接：Workbench 文件管理功能只对终端连接可用；会话管理（SSM）没有文件传输通道。
  • 下载慢：先当成网络或高峰期问题，不要立刻判脚本坏了。
  • 权限不足：先确认旧服务器账号是 root，或者至少能读目标路径。
如果要把问题交给 LLM，建议这样问：
  • 说明你执行的是哪份代码流。
  • 说明故障发生在主流程哪一步。
  • 附上最近 200 行终端输出。
  • 如果已经生成包，附上清单文件和校验文件。
  • 如果附件不完整，附上 attachment-files-found.tsv 和 attachment-files-missing.tsv。
  • 如果是 Windows 下载问题，附上下载路径和 05_windows_verify_bundle.ps1 的输出。
