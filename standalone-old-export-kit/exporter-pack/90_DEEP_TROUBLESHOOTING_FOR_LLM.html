复杂版排障说明

这个页面不是给普通导出执行者看的，而是给“排障者 / 接手迁移的人 / LLM”看的。 它把这套导出包背后的兼容性假设、已经规避的坑、以及异常时应该采集的材料写清楚， 目的是避免重复踩坑和重复试错。

推荐给 LLM 的文件集

  • 01_WORKBENCH_DIRECT_PASTE.txt 或 02_WORKBENCH_DOWNLOAD_SCRIPT.txt
  • Workbench 最近 200 行输出
  • 03_standalone_old_export.sh
  • 04_verify_export_bundle.sh 的输出
  • 若包已生成：manifest.txt、db-table-counts.tsv、upload-roots-included.txt
  • 若已导入：06_post_import_verify.sh 的输出

最重要的判断题

  • 问题发生在“导出阶段”还是“下载到 Windows 阶段”还是“导入后验证阶段”？
  • 当前 Workbench 连接方式是终端连接还是会话管理连接？
  • 失败的是数据库导出、附件收集、Workbench 下载、还是新库对账？
  • 是否有权限问题，例如不是 root、或者无权读取目标文件？

我在这次整理里刻意规避的坑

坑 为什么会踩 现在怎么规避
长命令被 Workbench 自动折行，导致命令被截成两段 直接把超长 raw URL、超长一行脚本、或局部片段复制进终端时，浏览器终端可能自动换行，肉眼还不容易发现。 提供完整复制粘贴版，尽量使用 heredoc 包裹脚本主体，并压短显式长行；文档明确要求“整文件复制”，不要只复制中间一段。
误以为“导出完成”就已经到 Windows 原流程只说明旧服务器产生了 tar.gz，但没有把“下载回本地”写成正式步骤。 现在把“旧服务器校验”与“Windows 下载/校验”升级为主流程步骤，而不是补充说明。
下载了文件，但本地拿到的是坏包 浏览器下载中断、重复开始、网络抖动都可能得到存在但损坏的文件。 导出脚本额外输出外层 .sha256，并提供 Windows 校验脚本。
Workbench 文件管理打不开 阿里云官方文档明确说明：会话管理连接不支持文件管理。 文档把“必须优先用终端连接”写成前置条件，并给出症状判断。
附件核对只看数据库 URL，不看落盘文件 数据库里的附件 URL 存在，不等于新系统磁盘上文件一定存在。 导出脚本新增 upload-relative-inventory.txt，导入后验证脚本逐个对照落盘文件。
导入后把所有表都要求“完全相等” 新系统 bootstrap 或修复逻辑可能补齐某些表，例如课程选课关系。 post_import_verify.sh 对核心主表做精确比较，对 course_enrollments 采用“不少于旧库”的标准。
兼容性判断要点： 这里的“版本兼容”不只指脚本语法，也包括 Workbench 版本、登录方式、包管理器差异、 旧系统路径差异、以及服务器是否自带 sha256sum / psql / pg_dump。 这套脚本已经尽量做了降级处理，但排障时必须先确认具体差在哪一层。

Workbench 相关兼容性

问题 说明
Workbench 1.0 / 2.0 阿里云官方文档当前同时描述了 1.0 和 2.0 的文件树入口，UI 不同，但都支持 Linux 文件下载。
终端连接 / 会话管理连接 文件管理功能不支持会话管理连接。看到实例名后带 ssm，或文件树里提示当前登录方式不支持，一般就是这个问题。
下载速度慢 阿里云官方文档明确提到高峰期传输可能变慢。不要把“慢”误判成“脚本坏了”。
文件权限不足 官方文档也明确要求使用 root 或具备目标文件读取权限的账号，否则下载可能失败。

脚本层兼容性

点 当前处理
包管理器差异 脚本按顺序兼容 apt-get、dnf、yum。
pg_dump 缺失 脚本会尝试自动安装 PostgreSQL client。
psql 缺失 脚本允许降级：数据库可导出，但会跳过附件引用清单与表统计。
sha256sum / shasum 缺失 脚本会降级跳过生成 SHA256 文件；这时应依赖结构校验与 tar -tzf 可读性确认。
旧系统路径不同 通过顶部变量 APP_NAME、ENV_FILE、RELEASE_DIR、OUT_DIR、EXTRA_UPLOAD_DIRS 覆盖。

大文件 / 传输策略判断

这部分不是原始脚本逻辑，而是排障时的策略建议。

  • 若 Workbench 文件管理可用，先用它下载，最简单。
  • 若 Workbench 文件管理不可用，先检查是否用了会话管理连接。
  • 若下载持续失败或速度极慢，改用 scp / sftp / OSS 中转，不要反复赌浏览器下载。
  • 若需要给导出者更低风险的方案，优先保留“直接粘贴版”，避免要求他们自己拼装命令。
为什么没有把所有内容都做成单行命令： 因为在 Workbench 里，短命令不一定比结构化 heredoc 更安全。对人类执行者来说， “整段复制粘贴，不要改中间内容”比“拼几行 curl + bash + 变量覆盖”更不容易出事故。

导入后验证为什么这样设计

  • 核心表使用精确比较：users、students、classes、subjects、homeworks、homework_submissions、course_materials、notifications。
  • course_enrollments 使用“新库不少于旧库”的比较，是为了兼容新系统导入或 bootstrap 可能修复出的额外选课数据。
  • 附件采用文件存在性清单，而不是靠 URL 推断，因为 URL 不等于落盘成功。
  • 复杂关系表没有一股脑全部纳入硬比较，是为了避免“工具太严反而误报”。
