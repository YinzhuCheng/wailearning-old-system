旧系统独立导出与迁移验证说明

本工具包用于从旧系统服务器导出迁移包，不要求旧系统仓库更新。 只要可以在阿里云 Workbench 以 root 登录旧服务器，通常就可以完成： 导出、下载到 Windows、本地校验、上传到新服务器、导入后核对。

优先使用哪一个文件

文件 用途
01_WORKBENCH_COPY_PASTE_EXPORT.txt 首选。完整复制粘贴即可执行，不依赖 GitHub。
02_WORKBENCH_DOWNLOAD_SCRIPT_EXPORT.txt 脚本版。会从公开 GitHub 下载 scripts/standalone_old_export.sh 和校验脚本。
scripts/standalone_old_export.sh 真正的导出脚本。可手动上传到服务器后执行。

整体迁移路径

  1. 在旧系统服务器导出一个 tar.gz 迁移包。
  2. 先在旧服务器校验迁移包结构和 SHA256。
  3. 把 tar.gz 和对应 .sha256 下载到 Windows。
  4. 在 Windows 上校验下载文件没有损坏。
  5. 把 tar.gz 上传到新系统服务器。
  6. 新系统恢复数据库、附件，再运行导入后验证脚本。

为什么不能只导出数据库

旧系统不是所有资料都只在数据库里。数据库保存用户、学生、班级、课程、 作业、通知等结构化数据，同时还保存附件 URL 和文件名； 但用户上传的真实文件通常落在服务器文件系统的 uploads 目录。 如果只导出数据库，迁移后页面可能还能看到记录，但附件会打不开。

因此本工具会同时尽量收集：

  • UPLOADS_DIR 指向的目录。
  • 旧 release 目录下的 uploads。
  • 应用根目录或 shared/uploads。
  • /opt 和 /root 下名为 uploads 的目录。

不记得数据库密码怎么办

旧系统部署后，数据库连接串通常写在 .env.production 或 .env 中。 脚本会自动查找这些文件并读取 DATABASE_URL， 所以执行者通常不需要手动输入数据库密码。

如果脚本仍提示找不到 DATABASE_URL， 说明旧系统部署路径和默认约定不同。可以先在服务器执行 find /opt /root -name .env.production 2>/dev/null， 找到真实路径后，修改操作流开头的 ENV_FILE。

导出包默认输出位置

/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz
/root/wailearning-migration/old-to-new-YYYYMMDDHHMMSS.tar.gz.sha256

注意：这里的“导出完成”只表示文件已经在旧服务器上生成， 不会自动下载到你本地 Windows。

操作步骤

方式一：完整复制粘贴版

  1. 打开 01_WORKBENCH_COPY_PASTE_EXPORT.txt。
  2. 如旧系统路径不是默认值，修改文件顶部变量。
  3. 全选整个文件，复制到阿里云 Workbench。
  4. 按回车等待导出结束。

方式二：下载脚本版

  1. 打开 02_WORKBENCH_DOWNLOAD_SCRIPT_EXPORT.txt。
  2. 全选复制到阿里云 Workbench。
  3. Workbench 会从公开 GitHub 下载脚本并执行。

旧服务器上的导出包校验

导出后先在旧服务器做一次包校验：

bash scripts/verify_export_bundle.sh /root/wailearning-migration/old-to-new-20260521120000.tar.gz

这一步至少会检查：

  • 外层 tar.gz 能否读取。
  • 是否包含 old-system.dump、old-uploads.tar.gz、manifest.txt 等关键文件。
  • 内部 old-uploads.tar.gz 能否解压。
  • 若存在 checksums.sha256，关键文件 SHA256 是否一致。
  • 若同目录存在外层 .sha256，是否与导出包匹配。

如何下载到 Windows

推荐下载这两个文件：

  • old-to-new-....tar.gz
  • old-to-new-....tar.gz.sha256

如果使用阿里云 Workbench，优先直接从 Workbench 文件管理器下载。 如果该路径没有可视下载入口，再用 scp / sftp 拉到 Windows。

不要只下载 .tar.gz 而不带 .sha256。 否则 Windows 上只能确认“文件存在”，不能确认“下载过程没有损坏或截断”。

Windows 本地校验

在 Windows PowerShell 执行：

powershell -ExecutionPolicy Bypass -File .\scripts\windows_verify_bundle.ps1 `
  -BundlePath C:\Users\you\Downloads\old-to-new-20260521120000.tar.gz `
  -Sha256File C:\Users\you\Downloads\old-to-new-20260521120000.tar.gz.sha256

如果不方便运行脚本，也可以直接用：

Get-FileHash C:\Users\you\Downloads\old-to-new-20260521120000.tar.gz -Algorithm SHA256

然后把输出 SHA256 与 .sha256 文件第一列比对。

导出包内容

文件 说明
old-system.dump PostgreSQL 自定义格式备份，用 pg_restore 导入。
old-uploads.tar.gz 尽量收集到的旧系统 uploads 文件。
old-env-file 旧环境变量快照，可能包含密码，请只交给可信迁移人员。
upload-roots-included.txt 脚本实际扫描并收集到的附件目录。
upload-relative-inventory.txt 打包进 old-uploads.tar.gz 的相对路径清单。
attachment-references.tsv 数据库内附件引用清单，用于检查是否有文件遗漏。
db-table-counts.tsv 导出时的旧库表统计，用于迁移后对账。
checksums.sha256 关键内部文件的 SHA256 摘要。
systemd/、nginx/ 旧部署配置快照，用于排查旧路径和反代规则。

导入后迁移验证

在新系统服务器执行：

BUNDLE_PATH=/path/to/old-to-new-20260521120000.tar.gz \
DATABASE_URL=postgres://... \
UPLOADS_DIR=/srv/wailearning/uploads \
bash scripts/post_import_verify.sh

这个脚本会做两类验证：

  • 数据库对账：重点校验 users、students、classes、subjects、homeworks、homework_submissions、course_materials、notifications。
  • 附件对账：如果提供 UPLOADS_DIR，会逐个检查旧包里的附件文件是否已存在于新系统目录。

course_enrollments 这类新系统可能自动修复或补齐的数据， 验证脚本采用“不少于旧库”的判断，而不是强制完全相等。

成功标准

阶段 最低成功标准
旧服务器导出 输出 导出完成，并给出一个 .tar.gz 路径。
旧服务器校验 verify_export_bundle.sh 通过。
Windows 下载校验 windows_verify_bundle.ps1 通过，或 Get-FileHash 与 .sha256 一致。
新服务器导入后验证 post_import_verify.sh 通过。

常见失败与处理

现象 处理
提示不是 root 用户 Workbench 重新用 root 登录，或先切换到 root。
找不到 DATABASE_URL 确认 ENV_FILE 指向真实旧系统 env 文件。
pg_dump 不存在 脚本会尝试安装 PostgreSQL client；如失败，先修复系统源。
导出包里附件为空 看 upload-roots-included.txt；如旧系统有自定义目录，补到 EXTRA_UPLOAD_DIRS。
Windows 校验 SHA256 不匹配 重新下载 .tar.gz 和 .sha256，不要直接拿损坏文件导入。
导入后表计数不一致 先看 post_import_verify.sh 报的是哪张表，再核对导入日志和新系统 bootstrap 行为。
导入后附件缺失 确认 old-uploads.tar.gz 是否已解压到新系统 UPLOADS_DIR 的父目录，并检查新系统配置路径。

给 LLM 排错时提供什么

  • 实际执行的 Workbench 操作流 txt。
  • Workbench 最近 200 行输出。
  • docs/old_export_guide.html。
  • scripts/standalone_old_export.sh。
  • scripts/verify_export_bundle.sh 或 scripts/post_import_verify.sh 的失败输出。
  • 如果包已生成，提供包内的 manifest.txt、db-table-counts.tsv、upload-roots-included.txt。

如果需要把材料给外部 LLM 或第三方，请先打码数据库密码、SECRET_KEY、 证书路径、公网 IP 和你不想公开的域名信息。
